# ERC-721 代码讲解

**源码**：[`erc-demo/erc721/DemoERC721.sol`](../../../erc-demo/erc721/DemoERC721.sol)  
**继承**：`ERC721` + `ERC721URIStorage` + `Ownable`。

---

## 1. 本合约自定义部分

### 1.1 `_nextId`（私有状态）

```solidity
uint256 private _nextId;
```

| 项 | 说明 |
|----|------|
| 作用 | 自增 `tokenId` 计数器；下一枚 NFT 的 id = 当前值，然后 `++`。 |
| 标准是否规定 id 分配 | **否**；可随机、可链下预定、可用 ERC-721Enumerable 枚举。 |
| 设计 | 简单可预测，适合教学；生产常用链下元数据表与 id 对齐。 |

### 1.2 `constructor(address initialOwner)`

```solidity
constructor(address initialOwner) ERC721("Demo ERC721", "D721") Ownable(initialOwner) {}
```

| 部分 | 对应标准/扩展 | 作用 |
|------|----------------|------|
| `ERC721(name, symbol)` | **EIP-721 元数据扩展** `IERC721Metadata` | 集合名称与符号（整集合共用，不是每个 token 一个 name） |
| `Ownable` | 非 721 | 限制谁可 `mint` |

### 1.3 `mint(address to, string calldata uri)`

```solidity
function mint(address to, string calldata uri) external onlyOwner returns (uint256 tokenId) {
  tokenId = _nextId++;
  _safeMint(to, tokenId);
  _setTokenURI(tokenId, uri);
}
```

| 步骤 | 函数 | 干什么 | 为何 |
|------|------|--------|------|
| 1 | `_nextId++` | 分配唯一 `tokenId` | 721 核心是「每个 id 唯一所有者」 |
| 2 | `_safeMint(to, tokenId)` | 铸造并 **安全** 转给 `to` | 若 `to` 是合约，会调 `onERC721Received`；拒绝则整笔 revert，避免 NFT 锁死 |
| 3 | `_setTokenURI(tokenId, uri)` | 写入该 id 的 metadata 链接 | 钱包/OpenSea 读 `tokenURI` 展示图片与属性 |

**标准里没有 `mint`**：铸造是项目自定义，但必须发出 `Transfer(from=0, to, tokenId)`（OZ `_mint` 已处理）。

### 1.4 `tokenURI` / `supportsInterface`（`override`）

```solidity
function tokenURI(uint256 tokenId) public view override(ERC721, ERC721URIStorage) returns (string memory)
function supportsInterface(bytes4 interfaceId) public view override(ERC721, ERC721URIStorage) returns (bool)
```

| 函数 | 为何写 `override` |
|------|-------------------|
| `tokenURI` | `ERC721` 与 `ERC721URIStorage` 都定义了路径；子合约必须显式指定用 **URI 存储扩展** 的版本（链上 per-token URI）。 |
| `supportsInterface` | 多继承下合并 `IERC721`、`IERC721Metadata`、`IERC4906`（若启用）等接口 id，供市场查询「这是不是 NFT」。 |

## 2. 标准接口 `IERC721`（EIP-721 必选）

规范：[EIP-721](https://eips.ethereum.org/EIPS/eip-721)

### 2.1 事件

| 事件 | 干什么 | 设计原因 |
|------|--------|----------|
| `Transfer(from, to, tokenId)` | 所有权变更 | 索引「谁拥有 #123」；`from=0` 铸造，`to=0` 销毁 |
| `Approval(owner, approved, tokenId)` | 单枚 token 的授权 | 拍卖市场可代转 **某一枚** |
| `ApprovalForAll(owner, operator, approved)` | 授权 operator 操作自己全部 NFT | OpenSea 等「一键挂单」依赖 |

### 2.2 视图函数

| 函数 | 干什么 | 与 ERC-20 差异 |
|------|--------|----------------|
| `balanceOf(owner)` | 持有 **枚数** | 20 是「数量」，721 是「几个 token」 |
| `ownerOf(tokenId)` | 该 id 当前主人 | **核心**：id → 地址 唯一 |
| `getApproved(tokenId)` | 该 id 被授权给谁 | 单枚级别 |
| `isApprovedForAll(owner, operator)` | 是否全权委托 | 集合级别 |

### 2.3 转移函数

| 函数 | 干什么 | 为何有 safe 版本 |
|------|--------|------------------|
| `transferFrom(from, to, tokenId)` | 普通转移 | 不检查接收合约能否处理 NFT |
| `safeTransferFrom(from, to, tokenId)` | 安全转移 | 调用 `IERC721Receiver.onERC721Received`；防止铸到无用合约 |
| `safeTransferFrom(..., data)` | 带 `data` 的安全转移 | 接收方可根据 `data` 做业务分支 |

### 2.4 授权函数

| 函数 | 干什么 |
|------|--------|
| `approve(to, tokenId)` | 授权 `to` 转走这一枚（转移后清除） |
| `setApprovalForAll(operator, approved)` | 授权/取消 operator 操作自己所有 token |

## 3. 元数据扩展 `IERC721Metadata`

| 函数 | Demo 中的值/行为 |
|------|------------------|
| `name()` | `"Demo ERC721"` |
| `symbol()` | `"D721"` |
| `tokenURI(tokenId)` | `mint` 时写入的 `uri`（如 `ipfs://...`） |

**设计原因**：链上只存 **URI 指针**，图片 JSON 多在 IPFS/HTTPS，节省 gas。

---

## 4. `IERC165` 与 `supportsInterface`

| 项 | 说明 |
|----|------|
| `supportsInterface(bytes4 interfaceId)` | 返回是否实现某接口（如 `0x80ac58cd` = ERC721） |
| 为何需要 | 市场、聚合器 **探测** 合约类型，避免把 NFT 当 20 转 |

---

## 5. 接收方接口 `IERC721Receiver`（标准必选之一）

```solidity
function onERC721Received(operator, from, tokenId, data) external returns (bytes4);
```

| 项 | 说明 |
|----|------|
| 何时调用 | `safeTransferFrom` / `_safeMint` 且 `to` 为合约时 |
| 返回值 | 必须为魔术值 `0x150b7a02`，否则 revert |
| 设计原因 | 让合约 **显式声明**「我能收 NFT」 |

---

## 6. `Ownable`（本合约）

仅 `owner` 可调用 `mint`；与 721 标准无关，属于权限层。

---

## 7. 数据模型对比（帮助记忆）

```text
ERC-20:  balanceOf[address] = amount
ERC-721: ownerOf[tokenId] = address   （每 tokenId 唯一）
         balanceOf[address] = 持有枚数
```
