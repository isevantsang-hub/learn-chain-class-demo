# ERC-2612（Permit）代码讲解

**源码**：[`erc-demo/erc2612/DemoERC20Permit.sol`](../../../erc-demo/erc2612/DemoERC20Permit.sol)  
**标准**：[EIP-2612](https://eips.ethereum.org/EIPS/eip-2612) — 对 **EIP-20** 的扩展，不是独立代币类型。  
**依赖**：[EIP-712](https://eips.ethereum.org/EIPS/eip-712) 结构化签名（OZ `ERC20Permit` 内实现）。

---

## 1. 继承关系

```text
DemoERC20Permit
  ├── ERC20          → IERC20 全部方法
  ├── ERC20Permit    → IERC20Permit（permit / nonces / DOMAIN_SEPARATOR）
  └── Ownable        → mint 权限
```

**为何 `ERC20Permit` 构造要传 name**：`"Demo Permit Token"` 用于计算 **DOMAIN_SEPARATOR**，必须与签名钱包显示的域一致，否则 `permit` 验证失败。

```solidity
constructor(address initialOwner)
  ERC20("Demo Permit Token", "DPERM")
  ERC20Permit("Demo Permit Token")  // name 字符串需与 ERC20 的 name 一致（OZ 要求）
  Ownable(initialOwner)
```

---

## 2. 本合约自定义部分

与 `DemoERC20` 相同逻辑：

| 成员 | 作用 |
|------|------|
| 构造内 `_mint(initialOwner, 1_000_000 * 10**18)` | 初始供应 |
| `mint(to, amount)` + `onlyOwner` | 增发（非 2612 标准） |

**其余转账、授权行为** 继承自 `ERC20`；**链下授权** 继承自 `ERC20Permit`。

## 3. 标准接口 `IERC20Permit`（EIP-2612）

OZ：[`IERC20Permit.sol`](../../../erc-demo/dependencies/@openzeppelin-contracts-5.6.0/token/ERC20/extensions/IERC20Permit.sol)

### 3.1 `permit(owner, spender, value, deadline, v, r, s)`

| 参数 | 干什么 |
|------|--------|
| `owner` | 代币拥有者（签名者） |
| `spender` | 被授权地址（如金库、Router） |
| `value` | 授权额度 |
| `deadline` | 签名过期时间戳，过期则 revert |
| `v, r, s` | ECDSA 签名分量 |

**链上逻辑（OZ 实现概要）**：

1. 用 `EIP-712` 拼 `Permit(owner,spender,value,nonce,deadline)` 结构体哈希；  
2. 结合 `DOMAIN_SEPARATOR` 得到 digest，恢复签名者地址 **必须等于 `owner`**；  
3. 检查 `nonce` 与 `nonces(owner)` 一致，成功后 **nonce++**；  
4. 写入 `allowance[owner][spender] = value`，发 `Approval` 事件。

| 设计原因 | 说明 |
|----------|------|
| 替代一笔 `approve` 交易 | 用户只签消息，relayer 或同一笔 tx 里提交 `permit` + `transferFrom` |
| `nonce` | 防重放：同一签名不能用两次 |
| `deadline` | 限制签名有效期，降低泄露风险 |

**安全注意（标准原文）**：`permit` 只表示授权额度，不表示用户意图；可被 frontrun，协议应 `try/catch permit` 并允许失败回退到普通 `approve`。

### 3.2 `nonces(address owner) → uint256`

| 项 | 说明 |
|----|------|
| 作用 | 当前 owner 的 permit 序号；签名里必须带此值 |
| 何时增加 | 每次成功 `permit` 后 +1 |
| 为何 | 即使相同参数，旧签名也因 nonce 变化而失效 |

### 3.3 `DOMAIN_SEPARATOR() → bytes32`

| 项 | 说明 |
|----|------|
| 作用 | EIP-712 域：`name`, `version`, `chainId`, `verifyingContract` 的哈希 |
| 为何需要 | 防止签名在 **另一条链** 或 **另一个合约** 上重放 |
| 课内测试 | `vm.sign` / 测试里用 `token.DOMAIN_SEPARATOR()` 构造 digest |

## 4. 仍适用的 `IERC20`（完整列表见 [ERC20-代码讲解](./ERC20-代码讲解.md)）

Permit **不替代** `transfer` / `transferFrom`：  
典型流程是 `permit` 设 allowance → `transferFrom` 拉款（见 `CrossAssetHub.depositWithPermit`）。

---

## 5. 签名结构（理解测试用）

类型哈希（OZ 固定）：

```text
Permit(address owner,address spender,uint256 value,uint256 nonce,uint256 deadline)
```

最终签名对象：

```text
digest = keccak256("\x19\x01" || DOMAIN_SEPARATOR || structHash)
```

[`test/erc2612/DemoERC20Permit.t.sol`](../../../erc-demo/test/erc2612/DemoERC20Permit.t.sol) 用 `vm.sign(ownerPk, digest)` 模拟钱包签名。

---

## 6. 与 EIP-3009 的区别（扩展阅读）

| | ERC-2612 | EIP-3009（如部分 USDC） |
|---|----------|-------------------------|
| 入口 | `permit` | `transferWithAuthorization` 等 |
| 结果 | 设置 `allowance` | 可直接转账 |
| 集成 | 需再 `transferFrom` | 一笔授权转账 |
