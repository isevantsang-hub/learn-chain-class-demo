# ERC-1155 代码讲解

**源码**：[`erc-demo/erc1155/DemoERC1155.sol`](../../../erc-demo/erc1155/DemoERC1155.sol)  
**标准**：[EIP-1155](https://eips.ethereum.org/EIPS/eip-1155)  
**继承**：`ERC1155` + `Ownable`。

---

## 1. 本合约自定义部分

### 1.1 常量 `ID_GOLD` / `ID_CARD`

```solidity
uint256 public constant ID_GOLD = 1;
uint256 public constant ID_CARD = 2;
```

| 项 | 说明 |
|----|------|
| 作用 | 业务 SKU：1=金币（可大量），2=稀有卡（通常少量） |
| 标准是否规定 id | **否**；id 由项目定义，可对应不同 metadata |
| 设计 | 用常量避免魔法数字，前端/测试可读 |

### 1.2 构造与 URI 模板

```solidity
constructor(address initialOwner) ERC1155("https://demo.example/api/{id}.json") Ownable(initialOwner) {}
```

| 项 | 说明 |
|----|------|
| `ERC1155(uri)` | **EIP-1155 元数据**：`{id}` 占位符，查询时用实际 `id` 替换 |
| 与 721 区别 | 721 常 per-token URI；1155 常 **按类型 id** 共用模板 |

### 1.3 `mintGold` / `mintCard` / `mintBatch`

| 函数 | 内部调用 | 干什么 |
|------|----------|--------|
| `mintGold(to, amount)` | `_mint(to, ID_GOLD, amount, "")` | 铸造金币 id |
| `mintCard(to, amount)` | `_mint(to, ID_CARD, amount, "")` | 铸造卡牌 id |
| `mintBatch(to, ids, amounts)` | `_mintBatch(...)` | 一次铸造多种 id |

| 修饰 | 说明 |
|------|------|
| `onlyOwner` | 铸造权集中；金库 `CrossAssetHub` 需成为 owner 才能代 mint |
| 第四参数 `data` | 标准预留；转发给接收 Hook 时用，Demo 传 `""` |

**标准无 `mint`**：与 20/721 一样，增发是项目逻辑，须发 `TransferSingle` / `TransferBatch`（OZ 已处理）。

## 2. 标准接口 `IERC1155`（EIP-1155 必选）

### 2.1 事件

| 事件 | 干什么 | 设计原因 |
|------|--------|----------|
| `TransferSingle(operator, from, to, id, value)` | 单种 id 转移 | 索引器按 id 统计流通量 |
| `TransferBatch(operator, from, to, ids, values)` | 多种 id 一批转移 | 空投 gas 更省 |
| `ApprovalForAll(account, operator, approved)` | 全权委托 | 游戏市场一次授权全部道具 |
| `URI(value, id)` | 某 id 的元数据 URI 变更 | 链上可更新（若实现 setURI） |

### 2.2 余额查询

| 函数 | 签名 | 干什么 |
|------|------|--------|
| `balanceOf` | `(account, id)` | 某账户在某 **id** 下的数量 |
| `balanceOfBatch` | `(accounts[], ids[])` | 批量查询，数组 **等长** |

**设计原因**：一个合约管理无限种 SKU，避免每种道具部署一个 ERC-20。

### 2.3 授权

| 函数 | 干什么 |
|------|--------|
| `setApprovalForAll(operator, approved)` | 授权 operator 转移自己 **所有 id** |
| `isApprovedForAll(account, operator)` | 查询是否已授权 |

**与 721 对比**：721 有「单枚 approve」+「ForAll」；1155 **只有 ForAll**（按规范简化）。

### 2.4 转移

| 函数 | 干什么 |
|------|--------|
| `safeTransferFrom(from, to, id, value, data)` | 安全转一种 id |
| `safeBatchTransferFrom(from, to, ids[], values[], data)` | 安全批量转 |

**safe**：若 `to` 是合约，调用 `IERC1155Receiver.onERC1155Received` 或 `onERC1155BatchReceived`，须返回魔术值，否则 revert。

**设计原因**：防止道具铸到无法处理的合约（与 721 safe 同理）。

## 3. 接收接口 `IERC1155Receiver`

| 回调 | 何时 |
|------|------|
| `onERC1155Received` | 单笔 safe 转入 |
| `onERC1155BatchReceived` | 批量 safe 转入 |

## 4. `IERC165`

`supportsInterface` 由 OZ `ERC1155` 实现，供市场识别「1155 合约」。

---

## 5. 账本模型（对比）

```text
ERC-20:   balance[holder]           → 一种代币一个数
ERC-1155: balance[holder][id]       → 一种合约、多种 id 各一个数
ERC-721:  ownerOf[tokenId]          → 每个 tokenId 唯一 owner
```
