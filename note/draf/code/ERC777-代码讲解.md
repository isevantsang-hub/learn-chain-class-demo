# ERC-777 代码讲解

**源码目录**：[`erc-demo/erc777/`](../../../erc-demo/erc777/)  
**标准**：[EIP-777](https://eips.ethereum.org/EIPS/eip-777) + [EIP-1820](https://eips.ethereum.org/EIPS/eip-1820)（接口注册表）  
**说明**：本仓库为 **精简教学实现**，非完整参考实现；生产新项目请优先 ERC-20。

| 文件 | 角色 |
|------|------|
| `IERC777.sol` | 标准接口子集 + Hook 接口 |
| `DemoERC777.sol` | 代币逻辑 |
| `ERC777Vault.sol` | 接收 Hook 示例 |
| `IERC1820RegistryMinimal.sol` | 本地测试用注册表 |

## 1. `IERC777` 接口（对照 EIP-777）

### 1.1 元数据与账本（与 ERC-20 类似）

| 函数 | 标准意图 | 干什么 | 设计原因 |
|------|----------|--------|----------|
| `name()` | 必选 | 代币名称 | 钱包展示 |
| `symbol()` | 必选 | 符号 | 交易对 |
| `granularity()` | 777 特有 | 最小可转移单位（Demo 固定 **1**） | 历史上为「不可分割最小单位」；与 20 的 decimals 概念不同 |
| `totalSupply()` | 必选 | 总供应 | 经济模型 |
| `balanceOf(account)` | 必选 | 余额 | 账本 |

### 1.2 发送（777 的核心：不用 `transfer`）

| 函数 | 干什么 | 与 ERC-20 对比 |
|------|--------|----------------|
| `send(recipient, amount, data)` | 从 **msg.sender** 转出，可带 `userData` | 20 用 `transfer`，无 data |
| `operatorSend(sender, recipient, amount, data, operatorData)` | **operator** 代 `sender` 转出 | 类似 `transferFrom`，但走 operator 权限模型 |

**Demo 中 `_send` 流程**（[`DemoERC777.sol`](../../../erc-demo/erc777/DemoERC777.sol)）：

```text
扣 from 余额
  → _callTokensToSend   （若 from 注册了 ERC777TokensSender）
  → 加 to 余额
  → _callTokensReceived （若 to 注册了 ERC777TokensRecipient）
  → emit Sent
```

| 设计原因 | 说明 |
|----------|------|
| Hook 在转账中间执行 | 接收合约可「支付即开通服务」 |
| 风险 | 外部调用可 **重入**；生态因此谨慎 |

`send(..., requireRecipient=true)`：若 `to` 是合约且 **未** 在 ERC-1820 注册接收实现，则 revert（防误转）；`operatorSend` 路径为 `false`。

### 1.3 Operator（运营商）模型

| 函数 | 干什么 | 为何 |
|------|--------|------|
| `authorizeOperator(operator)` | 允许 `operator` 代自己动币 | 类似长期授权，但是 777 专用 |
| `revokeOperator(operator)` | 取消 | 风控 |
| `isOperatorFor(operator, tokenHolder)` | 是否可代操作 | 链上检查 |
| `defaultOperators()` | 合约级默认 operator 列表 | Demo 返回空数组；构造时可设 `_defaultOperator` |

**与 ERC-20 `approve` 区别**：777 的 operator 可调用 `operatorSend` 直接完成转账，语义更接近「支付代扣」。

### 1.4 事件（Demo 实现）

| 事件 | 何时 |
|------|------|
| `Sent(operator, from, to, amount, data, operatorData)` | 每次 `_send` |
| `Minted(operator, to, amount, data, operatorData)` | `_mint` |

标准还有 `Burned` 等，Demo 未实现销毁。

## 2. Hook 接口

### 2.1 `IERC777Recipient.tokensReceived(...)`

```solidity
function tokensReceived(
  address operator,
  address from,
  address to,
  uint256 amount,
  bytes calldata userData,
  bytes calldata operatorData
) external;
```

| 参数 | 含义 |
|------|------|
| `operator` | 发起操作的地址（可能是 send 的 msg.sender） |
| `from` / `to` | 转出方 / 接收方 |
| `amount` | 数量 |
| `userData` / `operatorData` | 业务自定义载荷 |

**何时调用**：`_callTokensReceived` 在 **余额已加给 `to` 之后** 调用（Demo 顺序：先扣 from、sender hook、加 to、**再** recipient hook）。  
**注意**：与重入风险相关，读规范时要对照具体实现顺序。

### 2.2 `IERC777Sender.tokensToSend(...)`

在从 `from` 扣款后、到账前通知 **发送方** 注册的合约（若存在）。

## 3. `ERC777Vault`（[`ERC777Vault.sol`](../../../erc-demo/erc777/ERC777Vault.sol)）

| 部分 | 干什么 |
|------|--------|
| 构造 | `ERC1820.setInterfaceImplementer(this, ERC777TokensRecipient, this)` |
| `tokensReceived` | `totalReceived += amount`，记录 `lastSender` |

**教学点**：金库在 **收到 777 时自动记账**，等价于 Web2「支付回调」；ERC-20 更常见的是用户主动 `deposit()`。

## 4. `IERC1820RegistryMinimal`

| 函数 | 干什么 |
|------|--------|
| `setInterfaceImplementer(account, interfaceHash, implementer)` | 声明「某地址由 implementer 实现某接口」 |
| `getInterfaceImplementer(account, interfaceHash)` | 777 转账前查询 Hook 实现地址 |

**主网 canonical 地址**：`0x1820a4B7618BdE71Dce8cdc73aAB6C95905faD24`  
**Demo 测试**：部署 `ERC1820RegistryMinimal`，构造 `DemoERC777` / `Vault` 时传入该地址。

**设计原因**：避免每次转账都 `extcodesize` 猜测，改为 **显式注册**，减少误转；但增加基础设施依赖。

## 5. `DemoERC777` 构造参数

```solidity
constructor(name_, symbol_, initialSupply, defaultOps, erc1820Registry)
```

| 参数 | 作用 |
|------|------|
| `defaultOps` | 标记为默认 operator 的地址列表 |
| `erc1820Registry` | `address(0)` 时用主网 canonical 地址（本地测试应传部署的 Minimal 注册表） |

## 6. 为何课内不用 OZ 实现 777

OpenZeppelin 5.x **已移除** ERC777 官方实现；本仓库手写仅为理解 Hook。集成金库 **未** 使用 777，见 [Integration-代码讲解](./Integration-代码讲解.md)。
