# ERC-20 商业案例讲解

**一句话**：ERC-20 是以太坊上「可互换积分/货币」的通用格式。钱包、交易所、借贷协议只要认这一种接口，就能接入成千上万种代币，而无需为每种币单独开发。

配套演示合约：`erc-demo/erc20/DemoERC20.sol`（课内类比为「平台积分币」）。

---

## 1. 解决什么商业问题

| 商业诉求 | ERC-20 如何满足 |
|----------|-----------------|
| 统一结算单位 | 1 枚与另 1 枚完全等价，适合计价、工资、手续费 |
| 与第三方协作 | 用户 `approve` 后，DEX/借贷合约可代扣，无需把币先打进对方 EOA |
| 链上可审计 | `Transfer` 事件可被区块浏览器、合规工具索引 |
| 快速上线资产 | 发币门槛低于定制合约，利于测试网、活动币、治理票 |

## 2. 成熟商业案例（按业态）

### 2.1 稳定币：把法币流动性搬上链

- **USDT（Tether）**、**USDC（Circle）**、**DAI（MakerDAO）**  
  - **商业模式**：锚定美元（或一篮子资产），赚取储备收益、铸赎手续费或与 TradFi 结算差价。  
  - **为何用 ERC-20**：交易所、钱包、DeFi 默认识别；用户心智是「链上美元」。  
  - **业务要点**：合规（KYC/冻结能力在部分稳定币合约里）、储备透明度、脱锚风险。

### 2.2 DEX 与做市：流动性即商品

- **Uniswap**（V2 经典模型：两种 ERC-20 组成池子）  
  - **商业模式**：交易手续费分给 LP；协议在 V3 后另有手续费档位与 UNI 治理。  
  - **业务流**：用户提供 USDC/ETH 等 ERC-20 → 获得 LP 头寸（本身也常是 ERC-20）→ 交易者 swap 产生手续费。  
- **Curve**  
  - 专注稳定币等价值相近资产的大额兑换，降低滑点，服务机构与套利者。

**启示**：ERC-20 让「资产 A ↔ 资产 B」的交换可以标准化报价，交易所不必为每种币写一套托管逻辑。

### 2.3 借贷：存款即生息产品

- **Aave**、**Compound**  
  - **商业模式**：存款人获得利息（aToken/cToken 等收益凭证，多为 ERC-20）；借款人付息；协议抽成或靠代币激励。  
  - **业务流**：用户存入 USDC（ERC-20）→ 获得可转让的存款凭证 → 借款人抵押其他资产借出。  
  - **风险点**：清算、利率模型、抵押品价格波动——与标准无关，但资产层必须是可互换的 ERC-20 才便于定价。

### 2.4 治理与会员权益

- **UNI（Uniswap）**、**AAVE（Aave）**  
  - **商业模式**：持币投票改协议参数、财库支出、上币等；部分项目用 veToken 锁仓换投票权（仍是 ERC-20 生态扩展）。  
  - **业务价值**：把「股东/会员」权利代币化，降低跨国协调成本。

### 2.5 包装资产：把 BTC 带进 DeFi

- **WBTC**  
  - **商业模式**：托管方锁定 BTC，铸造等量 WBTC（ERC-20），用户可在以太坊上用 BTC 敞口做借贷、做市。  
  - **业务要点**：信任托管机构；适合「非原生链资产参与 DeFi」场景。

## 3. 典型用户旅程（商业视角）

```text
用户持有 USDC（ERC-20）
    → 在 Uniswap approve Router 花费额度
    → 一笔 swap 换成 ETH
    → 将 ETH 存入 Aave 赚息
```

每一步依赖的都是：**同一种余额账本 + 授权模型**。对产品来说，这意味着：

- 前端可以复用「连接钱包 → 选币 → 输入数量」组件；
- 商务合作方只需对接 ERC-20 地址与 decimals，无需知道你公司内部数据库里的用户 ID。

---

## 4. 与课内 Demo 的对应关系

| Demo 能力 | 商业类比 |
|-----------|----------|
| 固定初始供应 + owner `mint` | 活动运营方增发积分、空投补量（需风控） |
| `transfer` / `approve` | 用户转账、授权 DEX 扣款 |
| `decimals = 18` | 与 ETH 单位一致，方便 DeFi 公式（USDC 等用 6 位是历史例外） |

---

## 5. 商业风险与合规（产品必知）

- **无限授权**：用户 approve 过大额度，合约被攻破时损失放大 → 产品应引导「按需授权」或使用 Permit/Permit2。  
- **假币攻击**：同名不同合约 → 前端必须白名单代币地址。  
- **证券属性**：部分 ERC-20 在特定司法辖区可能被认定为证券，需法务评估。  
- **不可撤销转账**：转错地址无法像银行冲正 → 需二次确认与地址簿。

## 6. 何时选 ERC-20（决策表）

| 场景 | 是否适合 ERC-20 |
|------|-----------------|
| 平台积分、游戏金币（可互换） | 适合 |
| 会员卡「每一张编号不同」 | 不适合 → 考虑 721 / 1155 |
| 一批道具里有多档稀有度但同一合约 | 可考虑 1155 |
| 需要转账时自动通知接收合约 | 历史上曾用 777，现多改 20 + 显式回调 |
