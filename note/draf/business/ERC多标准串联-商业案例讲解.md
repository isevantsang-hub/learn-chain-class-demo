# ERC 多标准串联 · 商业案例讲解

**一句话**：真实产品很少只用一种标准，而是 **「钱」用 ERC-20、「身份/会员」用 721、「积分/道具」用 1155、「少一步授权」用 2612**。课内 `CrossAssetHub`（`erc-demo/integration/`）是这类组合的极简沙盘。

---

## 1. 为什么要串联（商业语言）

| 资产类型 | 常见标准 | 用户感知 |
|----------|----------|----------|
| 可替换的钱、稳定币 | ERC-20 | 「账户余额」 |
| 会员、门票、藏品 | ERC-721 | 「我有一张 VIP 卡」 |
| 游戏币、材料、批量券 | ERC-1155 | 「金币 500 + 稀有材料 3」 |
| 顺畅支付体验 | ERC-2612 | 「签一次名就完成充值」 |

**平台目标**：用户 **存一笔钱** → 自动获得 **可玩/可秀/可折扣** 的多层权益，提高留存与客单价。

---

## 2. 课内金库对应的商业故事

`CrossAssetHub` 规则（简化）：

| 用户行为 | 链上动作 | 商业含义 |
|----------|----------|----------|
| 存入 ≥ 100 单位支付币 | 铸造 1155 金币 | 充值达标送 **平台积分/游戏币** |
| 存入 ≥ 1000 单位 | 再铸造 721 会员 NFT | 大额客户升 **VIP 身份**（专属服务、治理、线下活动） |
| 使用 `depositWithPermit` | 免单独 approve | 降低充值流失，适合活动页拉新 |

这是典型的 **「储值 → 分层运营」** 模型，Web2 里类似：充 100 送积分、充 1000 升金卡。

## 3. 现实商业参照（非单一合约，但逻辑一致）

### 3.1 游戏 + 法币/稳定币入口

- **Stepn、各类 GameFi**（兴衰不一，模型可借鉴）  
  - 用户购入代币/道具（20）→ 游戏内消耗与 NFT 鞋（721）→ 赛季奖励多种道具（1155）。  
  - **收入**：道具销售、交易税、复活/修理费；**风险**：经济模型不可持续。

### 3.2 NFT 市场 + 竞价与会员

- **Blur**  
  - 交易 NFT（721）+ **积分/空投预期**（商业上类似 1155/20 积分混合运营，虽实现各异）。  
  - **模式**：低手续费抢流动性 → 积分激励交易者 → 代币与 NFT 空投。

### 3.3 社交与创作者

- **Friend.tech**（2023 现象级）  
  - **Keys** 可视为某种唯一身份凭证（721 类叙事）+ ETH 计价买卖；  
  - **启示**：「身份资产化」+ 二级市场，与「存款发会员」同属注意力经济。

### 3.4 品牌超级应用

- **Starbucks Odyssey / Nike .SWOOSH**  
  - 消费数据 → 多级数字权益（勋章、藏品、实体兑换）；  
  - 链上常混合 **20（结算）+ 1155（批量勋章）+ 721（限量联名）**。

### 3.5 DeFi 质押 + 治理 + NFT

- **Uniswap LP（20）+ UNI（20）+ 部分 POAP/纪念 NFT（721）**  
  - 同一用户旅程：提供流动性 → 赚手续费 → 持治理票 → 领取活动 NFT。  
  - **商业**：留住流动性提供者，用多资产类型叠加班层。

### 3.6 RWA 与基金份额（合规场景）

- 链上 **USDC（20）申购** → 份额凭证（721 表单一份额，或 1155 表多份相同份额）→ KYC 白名单；  
  - **要点**：商业核心在合规与托管，标准只是登记格式。

## 4. 串联架构（给产品 / 商务的画图模板）

```text
                    ┌──────────────────────────────┐
                    │        平台金库 / 托管         │
                    │  收：ERC-20（USDC 等）        │
                    │  发：1155 积分 / 721 会员      │
                    └──────────────────────────────┘
                              ▲
         deposit / permit      │
                              │
              ┌───────────────┴───────────────┐
              │           用户钱包              │
              │  持有 20 / 展示 721 / 游戏用 1155 │
              └───────────────────────────────┘
                              │
              ┌───────────────┴───────────────┐
              │  外部：OpenSea / DEX / 游戏客户端 │
              └───────────────────────────────┘
```

**分工**：

- **财务与结算**：ERC-20（对账简单）。  
- **品牌与 PR**：ERC-721（限量、故事性强）。  
- **日活与活动**：ERC-1155（大批量、低单价）。  
- **转化优化**：ERC-2612 / Permit2（少一步授权）。

## 5. 商业 KPI 如何拆到各标准

| KPI | 主要关联标准 | 观测方式 |
|-----|--------------|----------|
| 充值 GMV、首充转化 | 20 + 2612 | 金库入账事件、permit 使用率 |
| VIP 占比、ARPU | 721 | 会员 NFT 持有数、二级溢价 |
| 日活、任务完成 | 1155 | 金币消耗、批次空投领取率 |
| 拉新成本 | 2612 + 补贴 gas | 单笔获客链上成本 |

## 6. 运营与风控清单

- **分层阈值**（如 100 / 1000）需 A/B 测试，避免「鲸鱼」刷会员后抛售。  
- **721 会员权益** 要有链下履约（客服、线下活动），否则只剩炒作。  
- **1155 积分** 需防工作室批量小号充值（链上仅能解决一部分，需行为风控）。  
- **Permit 钓鱼**：活动页必须使用官方域名与合约地址公示。  
- **不要用 777** 做金库收款（见 [ERC777-商业案例讲解.md](./ERC777-商业案例讲解.md)）。

---

## 7. 从沙盘到真实项目的路径

1. **MVP**：只做 ERC-20 储值 + 中心化积分（验证 PMF）。  
2. **增长期**：加 1155 游戏化、2612 优化充值漏斗。  
3. **品牌期**：发 721 限量会员，对接 OpenSea 或自有市场。  
4. **合规期**：按辖区选择托管、KYC、证券定性，标准不变但流程变重。

课内 `forge test --match-path test/integration/**` 验证的是 **技术可串联**；上线前仍需经济模型与法务评审。
