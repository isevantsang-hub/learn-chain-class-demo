# 第 7 章：测试网——验证阶段警告 `Could not detect deployment`

## 7.1 是否算部署成功？

若日志末尾出现：

- **`ONCHAIN EXECUTION COMPLETE & SUCCESSFUL`**  
- **`Contract verification ... Pass - Verified`** / **`All (...) contracts were verified!`**

则 **部署与验证均成功**。  
中间的 **`Warning: Could not detect deployment...`** **不否定**部署本身。

---

## 7.2 警告在说什么？

典型文案：

```text
Warning: Could not detect deployment: Unable to locate ContractCode at 0x...; waiting 5 seconds before trying again (4 tries remaining)
```

**原因简述：** 广播刚结束就发起 **Etherscan 验证** 时，浏览器后端**可能尚未索引**到该地址的合约字节码，API 暂时返回「没有代码」。Foundry **会等待并重试**；索引跟上后常见 **`Pass - Verified`**。

因此多为 **索引/传播延迟**，**不是**「链上没部署成功」（除非重试仍失败且浏览器上也无代码）。

---

## 7.3 延迟常见原因

| 原因 | 说明 |
|------|------|
| 浏览器索引滞后 | 交易已确认，Etherscan 尚未暴露代码给验证 API |
| RPC 与浏览器数据源不一致 | 本地 RPC 已见收据，浏览器稍晚 |

---

## 7.4 处理策略

| 情况 | 做法 |
|------|------|
| **最终已 `Pass - Verified`** | **无需处理**，警告可忽略 |
| **反复失败** | 浏览器手动验证；或 **`forge verify-contract`**（参数见 `--help`）；或部署后等待 1～2 分钟再验证 |
| **始终未 verified 但浏览器 `#code` 有源码** | CLI 验证步骤失败，用手动补验证 |
| **浏览器上也无字节码** | 属于**部署未成功**类问题，不是本章索引警告 |

---

## 7.5 其它日志提示

- **`ETHERSCAN_API_KEY is set, defaulting to Etherscan verifier`**：正常，表示使用 Etherscan 验证后端。  
- **`broadcast/.../11155111/run-latest.json`**：Sepolia 链 ID **11155111**，便于查阅或 **`--resume`**。
